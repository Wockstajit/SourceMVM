# Easter-egg media

osu! songs are local-only. Only our generated `osu/SOURCE MVM - Warmup/` map is committed. `Automation/tools/make-osu-warmup-map.py` rebuilds it, and its audio is synthesized, so nothing is licensed. Other beatmap sets placed under `osu/` are local-only because they belong to other people, and `stage-easter-egg-media.ps1` copies whatever is there into the bundle. `osu-skin/` (a public skin) is committed.

`sony-vegas-sucks.mp4` is the master for the Sony Vegas intervention at render start (the easter-egg overlay in `AfxHookSource2/Filmmaker/Panorama/EasterEggVegasJs.h`). Only the master is version-controlled. The game plays an encoded copy.

`Automation/tools/stage-easter-egg-media.ps1` encodes it to `<content mount>\ui_override\panorama\videos\mvm_egg_vegas.webm` (VP9 + Vorbis, never upscaled; CS2's movie player plays an Opus track in silence). `build-source2.bat` step 8 and the launcher bundle both run it. The script re-encodes only when the master is newer than the staged file. `ui_override\` is mounted at the head of the search path (`main.cpp`), so Panorama resolves the clip as `file://{resources}/videos/mvm_egg_vegas.webm`.

To swap the clip, replace the master and rebuild, or run the script with `-Force`.

The overlay attaches to the main menu when no real level is loaded, and to the HUD during a map or demo. A retained HUD with zero layout at the menu cannot display the overlay. Context switches remove the current overlay before rebuilding it, and `mvm_debug` records the selected context and level. To inspect overlay counts and dimensions in each context, plus active hint boxes and label state, run [the read-only probe](../../Automation/verify/inspect-easter-eggs.js) through `livejs`. Hint animations pass their computed transform string directly between labels. Panorama's transform getter removes commas, so its result cannot safely be assigned back to a transform.

Outside osu!, Escape dismisses the current Vegas intervention, clears pending process-check results, and cancels the other active eggs. For backend verification, `mirv_filmmaker egg cancel` queues the same cancellation on the main thread. It refuses while osu! owns Escape. The overlay stops and clears the movie when it is dismissed or when render capture hides the chrome. Bringing the chrome back does not replay a stopped intervention. Use `egg vegas` when you want a fresh one.

Disco and Wes temporarily own the live light tint, amount, mode and sun yaw. While either effect is active, settings snapshots save the user's stashed values for those fields, including on explicit save and on shutdown. Other lighting edits still save normally. Switching between the two effects keeps the original stash, and cancelling restores it. If a session ends with an effect active, the recovery file stays available for startup.

Environment autosaves, named presets and Undo also use these original lighting values, while rendering still uses the live effect. Reloading a saved scene therefore cannot revive a newly saved Disco or Wes look after the egg has stopped. Files that already contain those colors need a known-good snapshot or an intentional lighting edit, because their colors alone do not identify them as temporary. Activation first writes and flushes a unique sibling file, then replaces the recovery file. If publishing fails, Disco and Wes stay off, the lighting and overlays stay unchanged, and the console reports the refusal. `mvm_debug` records the Windows write error, and you can retry after resolving it. Startup recovery accepts only a complete six-field stash with correctly typed, finite values inside the lighting controls' ranges. Invalid or oversized files leave the loaded user preferences untouched and stay on disk for diagnosis. A later activation writes a fresh stash. `mirv_filmmaker egg status` reports `lighting recovery: pending|none|restored|invalid|read-failed` and records that result, plus the active lighting ownership, in `mvm_debug` when logging is enabled.

`uwu/` holds the UwU (E-girl) egg's sounds. `music.mp3` loops at 10% while UwU is on, and pauses during osu! and renders. `bang.mp3` plays when a player dies. One of `pop1.mp3`..`pop4.mp3`, picked at random, plays on every gun shot. The bang and pop sounds are placed in the world, with distance falloff and direction from the camera (`EasterEggUwu.cpp`). `stage-easter-egg-media.ps1` copies them beside the hook into `<stage root>\bin\easter-eggs\uwu\`, where the hook decodes them once through the bundled ffmpeg. `music.mp3` is someone else's song, so it is git-ignored and local-only. Releases bundle it from the maintainer's copy. Without it (in a fresh clone), UwU has no music or beat pulse, but the bang and pops play.

`osu/` holds the beatmaps shipped with the osu! egg, one folder per mapset (`.osu` files, the song and its hitsound samples; no backgrounds, videos or storyboards). They are staged to `<stage root>\bin\osu\Songs\` and listed after the player's own osu!stable or lazer library. A set the player already has (same `.osu` MD5, or the same title, artist and mapper) is not listed twice.

`osu-skin/` holds the default osu! skin, used when the player has no osu! skin of their own (no osu! installed, or a built-in lazer skin selected): ExpressoKuns japan (WB) by Cappuccino, credited in the options screen. It is staged to `<stage root>\bin\osu\Skin\`. `OsuSkin.cpp` serves its images to the overlay and its sounds to the hitsounds.

The audio and images in `osu/` and `osu-skin/` are Git LFS files (`.gitattributes`).
