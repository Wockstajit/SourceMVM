# Cutting a release

Notes for the maintainer. Nothing here is needed to *use* SOURCE:MVM — see the
[README](README.md) for that.

A release has two halves that version independently:

- **The launcher** — `SourceMovieMaker-Setup-<version>.exe`, updated by `electron-updater`.
- **The runtime payload** — the hook and FX zips the launcher downloads, described by
  `payload-manifest.json`.

Both are uploaded to the same GitHub release, and the launcher resolves them from the newest
release that carries a manifest.

## 1. Stage the runtime payload

From the launcher directory in the development repository:

```bash
npm run build:payload
```

This reads the already-staged CS2 build — it never invokes CMake, compiles the hook, converts
FX, or starts CS2. Run `build-source2.bat` yourself first if the staged output is stale.

Output lands in `payload-dist/`. Add `-SkipFx` for a hook-only bump; the FX pack is ~230 MB
uncompressed and rarely changes.

> If you skip the FX pack, the release must still carry the previous `source-mvm-fx` asset, or
> the manifest will advertise a runtime with no FX pack beside it.

## 2. Build and publish the launcher

```bash
build-app.bat -Package
```

Then publish everything under one tag. The beta ships as a **pre-release**, which keeps this
repository's public "Latest release" empty until 1.0 while still reaching testers — the launcher
sets `allowPrerelease`, so it sees pre-releases.

```bash
gh release create v0.1.0 --repo Wockstajit/SourceMVM --prerelease --title "SOURCE:MVM 0.1.0" --notes "Beta." payload-dist/* release/SourceMovieMaker-Setup-0.1.0.exe release/latest.yml
```

`latest.yml` is what `electron-updater` reads. Leave it out and the launcher will never see the
new version.

## 3. Check it from a real install

Install the previous release, press **CHECK FOR UPDATES**, and confirm it offers the new one.

## Payload manifest

`payload-manifest.json` is generated by `build:payload`:

```json
{
  "schema": 1,
  "version": "0.1.0",
  "tag": "v0.1.0",
  "components": {
    "runtime": { "version": "…", "asset": "…", "bytes": 0, "sha256": "…", "url": "https://…" },
    "fx":      { "version": "…", "asset": "…", "bytes": 0, "sha256": "…", "url": "https://…" }
  }
}
```

`schema` must stay in step with `MANIFEST_SCHEMA` in the launcher's
`electron/runtime-payload.cjs`. Bumping it makes older launchers refuse the payload and tell the
user to update the app first — which is the point, but it strands anyone who does not update, so
bump it only for a genuinely incompatible layout change.

Component names (`runtime`, `fx`) and their unpack destinations are fixed in the launcher, not
taken from the manifest. A manifest cannot introduce a new component or redirect an existing one
somewhere else on disk.
